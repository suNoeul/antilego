### 알려진 결함 (전부 Spike 00 의 매핑 품질 문제 — 빌드는 스펙대로 돌았다)

1. **조사가 붙은 채로 밑줄되는 지명.** Spike 00 이 `josa_suspect: true` 로 표시한 장소가
   `places.json` 869곳 중 **255곳 · mention 421건(5.8%)** 이다. 실제로 ko 가 조사로 끝나는 것은
   자동 추정으로 **30곳 안팎 · mention 58건(0.8%)** (예: `힌놈의`, `호르산에`, `엘림에`, `우르에서`,
   `무라성에`, `라새아성에서`). 밑줄이 `[호르산에]` 처럼 한 글자 넓게 잡힌다.
   - **스펙의 조사 제거 재시도가 한 번도 발동하지 않은 이유가 이것이다.** 규칙상 재시도는
     "P.ko 를 본문에서 못 찾았을 때"만 도는데, `호르산에` 는 본문 `호르산에서` 안에 그대로 들어 있어
     **찾아진다.** 그래서 조사가 포함된 채 확정된다.
   - 무조건 조사를 떼는 쪽으로 규칙을 바꾸면 **더 나빠진다**: `므깃도→므깃`, `고린도→고린`,
     `데살로니가→데살로니`, `아세가→아세`, `비스가→비스`, `구브로→구브` 가 전부 잘린다.
     실제로 확인했다. 스펙 규칙이 옳다.
   - **고칠 자리는 데이터다.** Spike 00 이 예고한 수동 오버라이드 사전(`source: "manual"`)에서
     `ko` 를 고치면 빌드는 그대로 통과한다.

2. **명백한 오답 ko 가 밑줄로 나온다.** `Phoenix → 불편하므로`, `Syrtis → 쫓겨가더니`,
   `Adriatic Sea → 가까와지는`, `Cauda → 가우다라는`, `Shual → 노략꾼들이`, `Cnidus → 살모네`,
   `Allon → 상수리나무에서부`, `Bamah → 기브온`. 언급이 1~2건인 장소에서 F2 점수가
   같은 절의 아무 토큰이나 집은 결과다. confidence 0.99 가 붙어 있어 문턱으로는 못 거른다.
   같은 사전으로 지운다(ko = null 로 두면 자동으로 빠진다).

3. **일반명사를 지명으로 밑줄.** `남방`(Negeb), `평지`(Shephelah), `하수`(Nile), `대해`(Great Sea),
   `성소`, `증거궤`. 개역한글이 고유명사로 옮기지 않은 것들이라 밑줄이 어색하다.
   `하수`(conf 0.41)·`대해`(0.35) 는 문턱 0.6 에서 이미 걸러졌지만 `남방`·`평지` 는 통과한다.

4. **confidence 0.6 문턱이 큰 지명 하나를 잘랐다.** `Cyprus / 구브로` = 0.588.
   ko 는 맞는데 0.012 차이로 빠진다. 문턱을 0.55 로 낮추면 살아나지만 노이즈도 같이 늘어난다.
   판단은 Snow 몫이라 스펙 값(0.6)을 그대로 두었다.

5. **`1Sam.30` 이 30절이다.** 전자본 두 종이 모두 30:30–31 을 한 절로 합친다. 총 절 수는
   31,102 로 맞는다. 본문 전자본 결정(Spike 00 다음 할 일 5번)에서 같이 다룰 문제다.

1. **라벨 겹침 규칙을 넓혔다.** 스펙은 "focus 라벨과 겹치는 non-focus 라벨은 숨김"인데,

## D · 오버라이드 사전

실행: 2026-09-18 · Opus D · `data/derived/places.ko.overrides.json` (신규) + `build.py` 소폭 수정 + `web/data/` 재빌드.

A 가 남긴 "알려진 결함"은 전부 Spike 00 의 매핑 품질 문제였다. 자동 파이프라인을 다시 돌려도
살아남게 **`places.ko.json` 은 건드리지 않고** 별도 사전으로 덮었다.

```json
{ "a2e7601": { "ko": "구브로", "conf": 1.0, "en": "Cyprus", "cat": "add",
               "was": "구브로", "note": "…", "evidence": "Acts.27.4 …구브로 해안을 의지하고…" } }
```

`ko: null` 은 **억제**(어떤 절에서도 밑줄을 달지 않는다). `evidence` 는 전부 개역한글(bluesaurel)
본문에서 기계로 떠온 것이고, 생성기가 *(a) ko 가 그 절에 실제로 있는지 (b) 그 절이 OpenBible 의
해당 장소 구절 목록에 있는지* 를 단언(assert)으로 검사한다. 본문은 한 글자도 고치지 않았다.

### `build.py` 변경

`load_places_ko()` 가 `places.ko.json` 을 읽은 뒤 오버라이드를 덮고 `(ko_map, 적용 수, 억제 집합)`을
돌려준다. 오버라이드 항목은 `ko`/`confidence` 를 갈아끼우고 `source` 를 `"manual"` 로 표시한다.
`ko` 가 `null` 이면 기존 "ko 없음" 경로로 자연히 빠진다. 밑줄 규칙 자체는 손대지 않았다.
멱등성 유지 — 두 번 돌린 `web/data/` 전 파일 해시 동일 (`cdc6ee02…`).

#### `남방`·`평지` 를 억제한 이유

규칙은 "그 한글 낱말이 일반명사이고 지명이 아닌 자리에도 나타나면 억제"다. 둘 다 걸린다.

- `평지`(Shephelah) — 53절에 나오고 대부분 지명이 아니다. 왕상 10:27 `평지의 뽕나무`,
  왕상 20:23 `평지에서 저희와 싸우면`, 왕상 7:46 `요단 평지`. 이견 없이 억제.
- `남방`(Negeb) — 63절. 지역을 가리키는 자리(`유다 남방`, 삼상 30:1 `남방과 시글락`)도 있지만
  순수한 방위인 자리도 있다: 대상 26:15 `오벧에돔은 남방에 당첨되었고`, 대상 26:17
  `북방에 매일 네 사람이요 남방에 매일 네 사람이요`, 대하 4:10 `동남방에 두었더라`.
  **개역한글은 네게브를 고유명사로 옮기지 않는다.** 밑줄은 "고유명사 지명"이라는 약속이므로
  규칙대로 억제했다. 잃는 것은 mention 41건(남방) + 18건(평지) = 59건.

  **반론도 성립한다** — 창 12:9 `점점 남방으로 옮겨 갔더라`에서 이게 네게브 지역이라는 걸
  모르는 독자가 많고, 바로 그런 독자를 위한 도구다. 그리고 밑줄은 OpenBible 구절 목록으로
  이미 걸러지므로 대상 26:15 같은 자리에는 애초에 밑줄이 안 달린다.
  → **Snow 판단 필요.** 살리기로 하면 `ko`를 되돌리면 되고, 더 나은 답은 고유명사 밑줄과

#### V1. `position: sticky` 가 통째로 깨져 있다 — 상단바와 사이드 카드가 같이 스크롤돼 사라진다 (UI 버그)

`styles.css:45-52` 의

```css
html, body { … overflow-x: hidden; }
```

때문에 **`body` 가 스크롤 컨테이너가 된다**(계산값 `overflow: hidden / auto`). 그러면 그 후손인
`.topbar`(`position:sticky; top:0`)와 `#side-card`(`.sticky { position:sticky; top:64px }`)는

|---:|---:|---:|
| 0 | 0 | 76 |
| 1500 | **−1500** | **−1424** |
| 1500 (브라우저에서 `body.style.overflowX='visible'` 만 준 뒤) | **0** | **64** |

### V1 고침 — `body` 에서 `overflow-x` 를 뺐다 (`web/styles.css`)

전 (`styles.css:45-52`):

```css
html, body {
  margin: 0;
  background: var(--bg);
  color: var(--ink);
  font-family: var(--sans);
  -webkit-text-size-adjust: 100%;
  overflow-x: hidden;
}
```

후:

```css
html, body {
  margin: 0;
  background: var(--bg);
  color: var(--ink);
  font-family: var(--sans);
  -webkit-text-size-adjust: 100%;
}
/* overflow-x 는 html 에만 둔다. body 에 주면 body 가 스크롤 컨테이너가 되어
   .topbar / #side-card 의 position:sticky 가 통째로 깨진다 (RESULT.md V1). */
html { overflow-x: hidden; }
```

`html` 의 `overflow-x: hidden` 은 **뷰포트로 전파(propagate)** 되므로 `html` 자신이 스크롤 컨테이너가
되지 않는다. 그래서 sticky 가 살아 있다. 실측 계산값: `html.overflow-x = hidden`,
**`body.overflow-x = visible`, `body.overflow-y = visible`**, `body.scrollTop` 은 항상 0
(스크롤은 `documentElement` 가 받는다).
