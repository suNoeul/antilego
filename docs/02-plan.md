## Spike 00 — 한글 지명 매핑 (다음 작업, 담당: Codex 구현 / Claude 설계 리뷰)

**검증할 질문:** 영문 지명 → 한글 지명 매핑을 실용 수준으로 만들 수 있는가?
이게 안 되면 프로젝트가 성립하지 않는다. 그래서 여기부터.

### 첫 할 일 (순서대로)
1. **개역한글 전자 텍스트 확보** — `seven1m/open-bibles` 등 공개 리포지터리에 있는지, 원본과 일치하는지 확인.
   없으면 대안 조사. 이게 막히면 여기서 멈추고 보고.
2. 데이터 3종 `data/raw/` 에 내려받기 + 재현 스크립트 (`spikes/00-ko-place-mapping/fetch.sh` 등)
   - OpenBible 지오코딩 (장소 + 좌표 + 구절 목록)
   - STEPBible TIPNR
   - 개역한글 본문
3. OpenBible 장소 → **Wikidata ko 레이블** 자동 수집 → 커버리지 측정 (장소 수 / 언급 수 두 가지로)
4. 빈 칸에 대해 **구절 제약 후보 추출**: 그 장소가 나오는 구절들의 개역한글 본문에서 공통 한글 토큰
   (조사 처리: 접두 매칭 + 예외 사전으로 시작, 형태소 분석기는 필요할 때만)
5. 언급 빈도 상위 장소부터 수동 검증 (Snow)

### 성공 기준
성경 전체 지명 **언급 횟수** 기준 80% 이상이 한글 지명과 연결됨. (장소 개수 기준이 아님)

### 산출물
- `data/derived/places.ko.json` — place_id → { ko_krv, source: wikidata|verse|manual, confidence }
- `spikes/00-ko-place-mapping/RESULT.md` — 커버리지 수치, 실패 사례, 판정
- → 노션 Decisions에 한 줄

## Spike 01 — 읽기 UI 프로토타입

**검증할 질문:** 본문 옆 미니맵이 실제로 읽기 흐름을 덜 끊는가?

- 한 장만. 후보: 여호수아 10장 / 사도행전 27~28장 / 창세기 12장. Snow가 "지도 있었으면" 싶었던 장이 있으면 그게 우선

- 판정: Snow가 실제로 읽어보고 답한다
